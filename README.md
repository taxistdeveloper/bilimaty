# BILIMATY — College Education Management System

Информационная система управления учебным процессом колледжа (Республика Казахстан).
PHP 8.3 · собственный MVC · MySQL 8 (PDO) · Bootstrap 5.3 · Vanilla JS · kk / ru.

## Требования

- PHP 8.3+ с расширениями `pdo_mysql`, `mbstring`, `json`
- MySQL 8.0+ (или MariaDB 10.4+ из XAMPP; совместимость с MariaDB заложена, но не проверялась)
- Apache с `mod_rewrite` (OpenServer / XAMPP / MAMP)
- Composer (необязательно: без `vendor/` работает встроенный PSR-4 загрузчик)

Bootstrap, Bootstrap Icons и Chart.js лежат локально в `public/assets/vendor` —
интернет/CDN для работы не нужен.

## Установка

```bash
cp .env.example .env          # укажите DB_* и при желании SEED_ADMIN_*
composer install              # или composer dump-autoload
php cli.php db:create         # создаёт БД utf8mb4 (если пользователю разрешено)
php cli.php migrate
php cli.php db:seed           # роли, права, учебные годы 2025–2029, первый Super Admin
```

Если `SEED_ADMIN_PASSWORD` пуст, сидер сгенерирует пароль и **один раз** выведет его в консоль.
Сменить пароль: `php cli.php user:password admin`.

### OpenServer

1. Скопируйте проект в `domains/collegeos`.
2. В настройках домена укажите папку **`collegeos/public`** как корень домена
   (Настройки → Домены → «Ручное + автопоиск», папка `\collegeos\public`), модуль PHP 8.3, MySQL 8.
3. Выполните шаги установки в консоли OpenServer, откройте `http://collegeos/`.

### XAMPP

Вариант А (рекомендуется) — виртуальный хост `C:\xampp\apache\conf\extra\httpd-vhosts.conf`:

```apache
<VirtualHost *:80>
    ServerName collegeos.local
    DocumentRoot "C:/xampp/htdocs/collegeos/public"
    <Directory "C:/xampp/htdocs/collegeos/public">
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
```

и строка `127.0.0.1 collegeos.local` в `C:\Windows\System32\drivers\etc\hosts`.

Вариант Б — без vhost: положите проект в `htdocs/collegeos` и откройте
`http://localhost/collegeos/`. Корневой `.htaccess` перенаправит всё в `public/`,
а `app/`, `config/`, `storage/`, `.env` останутся недоступны из браузера.

### Встроенный сервер PHP (для разработки)

```bash
php -S 127.0.0.1:8000 -t public public/index.php
```

## Архитектура

```
public/index.php → bootstrap.php → App\Core\Application
  → Session / locale → Router (global csrf + route middleware) → Controller → Response
```

- `app/Core` — ядро: Router (параметры `{id:\d+}`, группы, middleware), Database (PDO, prepared
  statements, транзакции), Model (table gateway с белым списком колонок), View (layouts, sections,
  partials), Auth (сессия + RBAC), Session, CSRF, Validator, Translator, ErrorHandler, Migrator.
- `app/Middleware` — `auth`, `guest`, `csrf` (глобальный), `can:perm1,perm2`, `role:slug`.
- `app/Repositories` — все SQL-запросы; во View и контроллерах SQL нет.
- `app/Services` — `AuditLogger`, `LoginThrottle`.
- `config/permissions.php` — каталог прав и ролей (источник для RBAC-сидера).
- `config/navigation.php` — меню; ещё не реализованные модули отображаются неактивными с номером этапа.
- `routes/web.php`, `routes/api.php` (`/api/*`, единый JSON `{success, message, data[, errors]}`).

Таблица групп называется `` `groups` `` — это зарезервированное слово MySQL 8, в SQL всегда
берите его в обратные кавычки.

## Пользователи, роли и права (этап 2)

| Раздел | URL | Право |
|---|---|---|
| Профиль, смена пароля | `/profile`, `/profile/password` | любой вошедший пользователь (только свои данные) |
| Пользователи | `/users` | `users.view`; изменение — `users.manage` |
| Роли и матрица прав | `/roles` | `roles.manage` |
| Журнал аудита | `/audit` | `audit.view` |
| Настройки системы | `/settings` | `settings.manage` |

Правила доступа к записям (`app/Policies`):

- учётные записи Super Admin может изменять, блокировать и сбрасывать только Super Admin;
- свои роли и статус изменить нельзя, свой пароль — только в профиле;
- роль можно назначить, только если у назначающего есть все её **административные** права
  (`permissions.administrative` в `config/permissions.php`); роль super_admin назначает только Super Admin;
- в матрице прав не-супер-администратор включает/выключает только права, которые есть у него самого;
- системные роли и роли, назначенные пользователям, удалить нельзя.

Пароль, выданный администратором (или сгенерированный сидером / `user:password`), пользователь
обязан сменить при первом входе. Смена или сброс пароля и блокировка завершают все прочие сеансы
пользователя. Политика паролей: не менее 10 символов, буквы и цифры.

Важно: `php cli.php db:seed` приводит **системные** роли к `config/permissions.php` — изменения
прав системных ролей, сделанные через интерфейс, при этом будут перезаписаны. Права
пользовательских ролей сидер не трогает.

## Справочники, преподаватели, группы, студенты (этап 3)

| Раздел | URL | Право |
|---|---|---|
| Справочники: отделения, специальности, квалификации, дисциплины, аудитории | `/dictionaries` | `dictionaries.manage` |
| Преподаватели | `/teachers` | `teachers.view`; изменение — `teachers.manage` |
| Учебные группы | `/groups` | `groups.view`; изменение — `groups.manage` |
| Студенты: зачисление, перевод, статусы, история | `/students` | `students.view`; изменение — `students.manage` |
| API | `GET /api/groups`, `GET /api/groups/{id}/students` | `groups.view` (+ `students.view`) |
| Импорт студентов и преподавателей из Excel (.xlsx) или CSV с предварительной проверкой | `/import/students`, `/import/teachers` | `students.manage` / `teachers.manage` |

Простые справочники описаны в `config/dictionaries.php` и обслуживаются одним контроллером;
новый справочник добавляется описанием полей. Используемые записи не удаляются — их делают неактивными.

**Область доступа** (`App\Services\AccessScope`): роли из `permissions.college_wide_roles` видят весь
колледж; заведующий отделением — отделения, где он указан заведующим (`departments.head_teacher_id`);
куратор — свои группы. Ограничение действует в списках, карточках (подмена ID в URL → 403), API и
счётчиках главной страницы.

**Студенты.** При зачислении создаются учётная запись (логин из ФИО латиницей, временный пароль),
профиль и запись истории. Перевод закрывает период в старой группе днём раньше; смена статуса
закрывает текущий период; восстановление открывает новый. Отчисленные и переведённые в другую
организацию не могут войти. ИИН проверяется по контрольной цифре, полностью виден только при праве
`students.manage`, в журнал аудита не записывается.

Демо-данные для проверки (не на production): `php cli.php db:seed --demo` — 2 отделения,
3 специальности, 8 дисциплин, 6 аудиторий, 6 преподавателей, 4 группы, 40 студентов (без ИИН).

**Демо-режим «Посмотреть как»** (не на production): Super Admin видит в верхней панели кнопку с
глазом — список всех ролей. Один клик открывает систему под пользователем этой роли без пароля
(берётся пользователь с наименьшим набором прав), сверху — жёлтая плашка и кнопка «Вернуться к
администратору». Язык интерфейса ведущего сохраняется. Переключение пишется в журнал аудита
(`auth.demo_switch`). Пользователей для ролей без демо-людей (администратор, заместитель директора,
учебная часть, кадры, родитель со связанным студентом) создаёт `DemoRolesSeeder` в составе
`db:seed --demo`.

**Витрина для показа** (`DemoShowcaseSeeder`, тоже в `db:seed --demo`, один раз): темы и задания
всех занятий; учебные планы всех групп; прошлый учебный год у групп 2 курса (журналы, оценки,
рейтинги, закрытые экзаменационные ведомости, пересдача, утверждённые журналы, выданные
транскрипты); экзамены зимней сессии (запланированы); заявления студентов во всех статусах;
4 анкеты с ответами (открытые, закрытая, черновик); личные дела сотрудников, приказы, отпуска,
командировка, курсы повышения квалификации и напоминания; второй ребёнок у демо-родителя.
Для роли «Студент» в «Посмотреть как» закреплена студентка 2 курса с полной историей
(`settings.demo_role_users`).

## Учебный процесс (этап 4)

| Раздел | URL | Право |
|---|---|---|
| Учебные годы и семестры | `/academic-years` | `academic_years.manage` |
| Академический календарь | `/calendar` | `calendar.view`; изменение — `calendar.manage` |
| Учебные планы | `/curricula` | `curricula.view`; изменение — `curricula.manage` |

- **Учебный год**: название формируется по датам; год не длиннее 13 месяцев и не пересекается с другими;
  семестры внутри года и не перекрываются. Активация переводит прежний активный год в архив (если он
  завершён) или в «запланирован». Архивный год доступен только для чтения; удалить можно лишь пустой
  неактивный год.
- **Календарь**: событие относится ко всему колледжу, к курсу или к группе. Студент видит календарь
  только своей группы. Семестры берутся из таблицы `semesters`, а не дублируются событиями.
  Государственные праздники с фиксированной датой добавляются кнопкой из `config/holidays.php` —
  сверьте список с действующим законом; Курбан айт и переносы выходных вносятся вручную.
- **Учебный план**: черновик → утверждён (только чтение) → архив; копирование на новый год набора.
  Теория + практика + лабораторные ≤ общих часов (проверяется и в БД). Кредиты хранятся, но не
  пересчитываются: правила колледжа не заложены. План привязывается к группе той же специальности.
- **PDF**: календарь и учебный план открываются A4-страницей «PDF / печать» — браузер сохраняет её в
  PDF. Серверная генерация PDF не подключена (см. «Зависимости»).

После обновления выполните `php cli.php migrate` и `php cli.php db:seed` (добавляется право `curricula.view`).

## Расписание занятий (этап 5)

| Раздел | URL | Право |
|---|---|---|
| Расписание (неделя / день; группа, преподаватель, аудитория) | `/schedule` | `schedule.view` |
| Добавление и изменение регулярных занятий (модальное окно, Fetch) | `POST/PUT/DELETE /api/schedule` | `schedule.manage` |
| Замена, смена аудитории, отмена, перенос конкретного занятия | `/schedule/entries/{id}/changes` | `schedule.manage` |
| Журнал изменений | `/schedule/changes` | `schedule.view` |
| Расписание звонков | `/dictionaries/lesson_periods` | `dictionaries.manage` |

- **Конфликты** проверяются в одном семестре, дне и паре при пересекающейся чётности недель
  («каждая» пересекается с любой): преподаватель, аудитория и группа не могут быть заняты дважды;
  подгруппы 1 и 2 могут заниматься одновременно, но не вместе со всей группой. Те же правила
  действуют для замен и переносов на конкретную дату. Запись выполняется под блокировкой
  `GET_LOCK` на семестр, чтобы два диспетчера не создали конфликт одновременно.
- **Чётность недели** считается от недели начала семестра (она нечётная). Настройки — `config/schedule.php`.
- Если группе назначен учебный план, дисциплина должна быть в нём для текущего семестра обучения
  (семестр обучения = (курс − 1) × 2 + номер семестра).
- В дни событий календаря из `schedule.suspending_event_types` (каникулы, праздники, сессия,
  практика, итоговая аттестация) регулярные занятия группы показываются как «не проводятся».
- Студент по умолчанию видит расписание своей группы, преподаватель — своё; на главной странице
  выводятся занятия на сегодня. Замещающий преподаватель видит занятие у себя, замещаемый — с пометкой.
- API: `GET /api/schedule?semester=&from=&to=&group=|teacher=|classroom=` (не более 31 дня),
  ошибки и конфликты — `422 {"errors": {"conflicts": [...]}}`.

## Электронный журнал (этап 6)

| Раздел | URL | Право |
|---|---|---|
| Журналы (список, сетка, история, экспорт CSV, печать) | `/journal` | `journal.view` / `journal.manage` |
| Автосохранение ячеек (Fetch) | `GET /api/journals/{id}`, `POST /api/journals/{id}/grades` | `journal.manage` |
| Утверждение, возврат на доработку | `/journal/{id}/status` | `journal.approve` |
| Создание журналов, настройки, заполнение дат | `/journal`, `/journal/generate` | `schedule.manage` или `journal.approve` |
| Схемы оценивания | `/grading-schemes` | `grading.manage` |
| Мои оценки (студент видит только себя) | `/journal/my` | `journal.view` |

- **Журнал** = семестр + группа + дисциплина + ответственный преподаватель. Вести его могут также
  преподаватели, у которых эта дисциплина у группы стоит в расписании. Куратор и заведующий видят
  журналы своих групп, но не вводят оценки.
- **Студенты журнала** берутся из истории групп за период семестра; оценку можно поставить только на
  дату, когда студент числился в группе.
- **Ввод**: число по шкале схемы (запятая или точка, до 2 знаков), «н» — отсутствовал, «у» —
  по уважительной причине; комментарий — правый клик или Alt+Enter. Каждое изменение пишется в
  `grade_change_history` (кто, когда, было → стало).
- **Итог** = Σ(вес × компонент) / Σ весов по **схеме, утверждённой администрацией** (веса, шкала,
  порог, число знаков). Встроенной формулы нет; если не хватает компонента — итог не рассчитывается.
  Утверждённая схема неизменяема, новые правила — новая версия.
- **Статусы**: ведётся → сдан → утверждён. При утверждении итоговые фиксируются в
  `student_assessments` вместе с версией схемы. Настройка «Блокировка журнала после утверждения»
  запрещает изменения; если она выключена, зафиксированный итог пересчитывается при правках.
  Возврат на доработку — с указанием причины, зафиксированные итоги снимаются.
- **Экспорт**: CSV (UTF-8 с BOM, разделитель «;») открывается в Excel; печать A4 — через браузер.
  Формат .xlsx требует PhpSpreadsheet (см. «Зависимости и сеть»).

## Рейтинги, экзамены и транскрипты (этап 7)

| Раздел | URL | Право |
|---|---|---|
| Расписание рейтингов и экзаменов | `/exams` | `exams.view` (назначение — `exams.manage`) |
| Ведомость, закрытие, повторное открытие, печать A4 | `/exams/{id}`, `/exams/{id}/print` | экзаменатор или преподаватель журнала; открыть повторно — `exams.manage` |
| Пересдачи | `/exams/{id}/retakes` | назначить/отменить — `exams.manage`, результат — экзаменатор пересдачи |
| Мои экзамены (студент) | `/exams/my` | `exams.view` |
| Транскрипты: предпросмотр, выдача, документ, CSV, аннулирование | `/students/{id}/transcript`, `/transcripts` | `transcripts.view` / `transcripts.issue` |
| Публичная проверка подлинности (без входа) | `/verify/{код}` | — |
| API транскрипта | `GET /api/students/{id}/transcript` | `transcripts.view` |

- **Событие** (рейтинг или экзамен) назначается журналу только для вида контроля, который входит в
  схему оценивания журнала как вводимый компонент. Проверяются даты семестра и конфликты:
  у группы в этот день, у экзаменатора и в аудитории в это время. Номер ведомости `В-ГГГГ-NNNNN`.
- **Ведомость**: допуск, явка, оценка по шкале схемы. Оценку можно поставить только допущенному и
  явившемуся. При закрытии нужна явка всех допущенных, и оценки переносятся в журнал
  (`student_assessments`, история в `grade_change_history`). Ячейка такого компонента в журнале
  только для чтения. Если журнал утверждён, зафиксированный итог пересчитывается.
- **Пересдача** назначается после закрытия ведомости. Попытки нумеруются и не удаляются: хранятся
  прежняя и новая оценки, основание, приказ и экзаменатор. Результат («не явился» или оценка)
  обновляет ведомость и журнал.
- **Транскрипт** собирается только из **утверждённых** журналов. Часы берутся по учебному плану,
  а если план не назначен — по фактически проведённым занятиям (помечены «*»).
  - Буквенная оценка и GPA выводятся **только при утверждённой шкале** (`config/transcript.php`).
    По умолчанию шкала не задана, и GPA не рассчитывается.
  - Выданный документ — неизменяемый снимок: номер `T-ГГГГ-NNNNN`, 32-символьный код проверки
    и контрольный код SHA-256.
  - Аннулирование выполняется с указанием причины; документ при этом не удаляется.
- **QR-код** формируется на сервере без внешних сервисов (`App\Helpers\QrCode`, SVG). Он ведёт на
  `APP_URL/verify/{код}`, поэтому укажите в `.env` реальный адрес колледжа.
  Страница проверки показывает только номер, дату, статус, число дисциплин и контрольный код —
  без ФИО и оценок.
- **PDF**: ведомость и транскрипт открываются как A4-страницы и сохраняются в PDF из окна печати
  браузера. Серверная генерация PDF требует библиотеки Composer (см. «Зависимости и сеть»).

## Учебная нагрузка (этап 8)

| Раздел | URL | Право |
|---|---|---|
| Нагрузка преподавателей за учебный год (план, факт, остаток, лимит) | `/workload` | `workload.view` |
| План преподавателя: ставка, лимит, распределение часов, утверждение | `/workload/teachers/{id}` | просмотр — `workload.view`, планирование — `workload.manage` |
| Строка нагрузки и фактические часы (ручной учёт) | `/workload/assignments/{id}` | `workload.manage` или сам преподаватель |
| Отчёты: преподаватели, отделения, группы, дисциплины, виды, семестры, подробный план-факт; CSV и печать A4 | `/workload/reports` | `workload.view` |
| Справочник видов нагрузки | `/dictionaries/workload_types` | `dictionaries.manage` |

- **Виды нагрузки** — настраиваемый справочник. Вид можно связать:
  - с типом занятия журнала, тогда факт считается по проведённым занятиям;
  - с колонкой учебного плана (теория, практика, лабораторные), тогда объём ограничен учебным планом группы.
  Изначально заведены: теория, практика, лабораторные, консультации, экзамены, практика (производственная/учебная), другое.
- **План** создаётся на преподавателя и учебный год: ставка и лимит часов. Лимит задаёт администрация,
  встроенной нормы нет. Статусы: черновик → утверждён. Вернуть на доработку можно только с указанием основания.
- **Распределение часов**: семестр, группа, дисциплина, вид, подгруппа. Контроль:
  - сумма по строке учебного плана у всех преподавателей не превышает объём колонки
    (целая группа плюс каждая подгруппа);
  - план не превышает лимит преподавателя;
  - повторяющиеся строки не допускаются.
  Кнопка «Заполнить по учебному плану» добавляет нераспределённые часы по журналам преподавателя.
- **Факт**:
  - для видов, связанных с журналом, — часы занятий до выбранной даты. Часы засчитываются тому, кто
    фактически провёл занятие, то есть с учётом замен. Такие часы без плановой строки показываются
    как «вне плана»;
  - для остальных видов факт вносится вручную: дата, часы, примечание.
  Остаток и процент выполнения считаются только по плановым строкам.
- **Excel и PDF**: CSV (UTF-8 с BOM, разделитель «;») открывается в Excel; PDF — через печать A4 в браузере.

## Практика

| Раздел | URL | Право |
|---|---|---|
| Список практик, назначение руководителю | `/practice`, `/practice/create` | `practice.view`; назначение и приёмка — `practice.manage` |
| График программы прохождения практики (заполнение) | `/practice/{id}` | `practice.fill` — только свой |
| Практики на дату | `/practice/day` | `practice.view`, `practice.fill` |
| Печать графика (шаблон «Утверждено зам. директора по УПР») | `/practice/{id}/print` | как у карточки |

Логика перенесена из прототипа «Графики преподавателей»: учебная часть назначает руководителю
практику (наименование, вид, группа, модуль, часы, срок сдачи графика); руководитель заполняет
строки: модуль, раздел, тема; дата; начало и окончание; место; ДОТ (для ДОТ — платформа или
ссылка). Часы считаются автоматически (окончание − начало). Суббота, воскресенье и праздники
академического календаря (`public_holiday`) в зачёт не идут. Черновик сохраняется в любой момент.
Отправить график можно, только когда все строки заполнены, нет выходных и праздников, занятия
одного дня не пересекаются и набрано ровно назначенное число часов. Учебная часть утверждает
график или возвращает его на доработку с причиной. «Просрочено» — срок сдачи прошёл, а график
не отправлен. О назначении, отправке, утверждении и возврате приходят уведомления.
Права: администратор, заместитель директора и учебная часть назначают и принимают графики,
заведующий отделением видит практики своих групп, преподаватель заполняет свои.
Демо-практики во всех статусах создаёт `DemoPracticeSeeder` в составе `db:seed --demo`.

| Раздел | URL | Право |

  - справка с номером `С-ГГГГ-NNNNN` — неизменяемый снимок данных, QR-код и проверка на `/verify`;
  - официальный транскрипт (этап 7);
  - внесение одобренных изменений в персональные данные, с повторной проверкой ИИН и e-mail на уникальность;
  - без автоматического документа.
- **История**: каждая смена статуса и комментарий записываются. Служебные заметки студент не видит.
- **Уведомления** (колокольчик) пишутся на языке получателя:
  - студенту — о каждом решении и комментарии;
  - сотрудникам с правом `documents.process` (ролям уровня колледжа и заведующему отделением студента) — о новых и повторно отправленных заявлениях.
- **Файлы**: PDF, JPG или PNG до 5 МБ. Тип определяется по содержимому файла.
  Файлы хранятся в `storage/private/documents` под случайными именами и выдаются только заявителю и сотрудникам.
- **Реквизиты справки** (адрес колледжа, должность и ФИО подписанта) задаются в «Настройки → Справки и документы».

## Анкетирование (этап 10)

| Раздел | URL | Право |
|---|---|---|
| Анкеты для меня, прохождение | `/surveys`, `/surveys/{id}` | `surveys.respond` |
| Конструктор: параметры, вопросы, публикация, закрытие, копия | `/surveys/create`, `/surveys/{id}/edit` | `surveys.manage` |
| Результаты: графики, сравнение, CSV, печать A4 | `/surveys/{id}/results` | `surveys.results` или `surveys.manage` |

- **Анкета**: название и описание (рус./каз.), период проведения и целевая аудитория. Аудитория — студенты, преподаватели или все; её можно сузить до отделения, курса или группы. Статусы: черновик → опубликована → закрыта.
  - После публикации вопросы, аудиторию и режим изменить нельзя; меняются только тексты и дата окончания.
  - Чтобы повторить опрос и сравнить результаты, создайте копию анкеты.
- **Вопросы**: один вариант, несколько вариантов, текстовый ответ, шкала оценивания (от 0 до 10, с подписями краёв). Вопрос может быть обязательным. Вопросы можно переставлять.
- **Анонимный режим**:
  - ответ хранится без идентификатора пользователя и без точного времени, только дата;
  - факт участия хранится в `survey_participants`: без ссылки на ответ, без времени и без порядка вставки;
  - для сравнения сохраняются только крупные признаки (роль, отделение, курс); группа не сохраняется;
  - в сравнении скрываются группы респондентов меньше 3 человек;
  - текстовые ответы показываются в алфавитном порядке, выгрузка перемешана и не содержит имён;
  - в журнал аудита пишется только факт ответа.
- **Именная анкета**: виден список ответивших, в выгрузке есть ФИО и группа.
- **Статистика** (Chart.js):
  - число участников и процент прохождения от целевой аудитории;
  - распределение ответов и средние оценки по шкалам;
  - сравнение по роли, отделению, курсу, а для именных анкет и по группе.
- На главной студенту и преподавателю показывается напоминание о непройденных анкетах.

| Раздел | URL | Право |
|---|---|---|
| Отчёты: успеваемость, посещаемость, нагрузка, анкеты | `/reports` | `reports.view` (и права модулей) |
| Успеваемость группы за семестр: итоги по всем дисциплинам, задолженности; CSV и печать A4 | `/reports/performance` | `reports.view` |
| Посещаемость группы: пропуски по дисциплинам, % посещённых занятий; CSV и печать A4 | `/reports/attendance` | `reports.view` |
| Мои группы (преподаваемые и курируемые) | `/groups/my` | преподаватель |

| Мои оценки (студент) | `/grades` (старый адрес `/journal/my` перенаправляет) | студент |

Кто что видит в отчётах:
- администрация, заведующие и кураторы — группы своей области доступа, все дисциплины;
- преподаватель — группы, где он ведёт занятия, и только свои дисциплины.

Итоги берутся из журнала по утверждённой схеме: своей формулы отчёты не вводят.

**Печатные формы по приказу № 130** (Приказ Министра образования и науки РК от 6 апреля 2020 года
№ 130, приложение 8, формы для ТиПО; сверено с редакцией по изменениям до 15.07.2026). Кнопка
«Печать» выводит бланк, браузер сохраняет его в PDF:
- журнал (`/journal/{id}/print`) — «Журнал учета теоретического обучения»: титульный лист
  (группа, курс, специальность, квалификация, учебный год), содержание, форма № 5.3 «Учет
  посещаемости занятий и успеваемости обучающихся» (левая сторона — оценки и «н», правая —
  дата, часы, темы, подпись педагога, «Итого по модулю»), лист замечаний;
- успеваемость (`/reports/performance?format=print`) — форма № 5.5 «Итоги учебно-воспитательной
  работы» за учебный год: 1-е и 2-е полугодие, рейтинг допуска, зачёт, экзамен, итоговая оценка,
  часы по учебному плану и фактически данные;
- посещаемость (`/reports/attendance?format=print`) — форма № 5.5, «Пропущено часов»: по
  полугодиям и за год, всего и по неуважительным причинам;
- экзамен (`/exams/{id}/print`) — «Экзаменационная ведомость (для промежуточной аттестации)».

Допущения, которые нужно сверить с колледжем: приказ определяет рейтинг допуска только как
среднее арифметическое, без перечня оценок. В бланках это среднее рейтингов Р1 и Р2 схемы
оценивания (`App\Services\Order130::RATING_CODES`). Индекс модуля, часы по плану и вид контроля
(зачёт или экзамен) берутся из учебного плана группы; если план не назначен, графы остаются пустыми.
В форме № 5.3 любое отсутствие отмечается буквой «н», как в приказе, а причина учитывается
в форме № 5.5. Казахский текст бланков переведён в приложении, его нужно сверить с официальным
текстом приказа на казахском языке.

## Импорт из Excel

1. **Загрузка.** На странице «Студенты» или «Преподаватели» нажмите «Импорт из Excel». Можно скачать шаблон.
   - Подходит файл `.xlsx` или `.csv`, до 5 МБ и 2000 строк.
   - Колонки узнаются по заголовкам на русском или казахском языке, порядок не важен. Нераспознанные колонки пропускаются, а система сообщает о них.
   - Значения можно писать по-человечески: группа — кодом, пол — «М/Ж», финансирование — «грант/платно», даты — `ДД.ММ.ГГГГ` или как дату Excel.
2. **Проверка.** Каждая строка проверяется по тем же правилам, что и ручная форма:
   - корректность и уникальность ИИН, e-mail и номеров;
   - существование группы или отделения и то, что они входят в вашу область доступа;
   - повторы внутри самого файла.
   В базу на этом шаге ничего не записывается.
3. **Импорт.** Импортируются только строки без ошибок, каждая — со своей учётной записью и историей зачисления.
   Логины и временные пароли показываются один раз и скачиваются одним CSV, после скачивания удаляются. При первом входе пароль нужно сменить.

Файл читается встроенными расширениями PHP (`zip`, `xmlreader`), без сторонних библиотек. Защищено от слишком больших и «распаковывающихся» файлов.

## Отдел кадров (HR)

Роль **«Отдел кадров»** (`hr`): права `hr.view`, `hr.manage`, `leave.request`. Заведующий отделением видит сотрудников только своих отделений и только для чтения (`hr.view`); ИИН, дата рождения и адрес показываются лишь с правом `hr.manage`. Подать заявку на отпуск может любой сотрудник с правом `leave.request` (раздел «Мои отпуска»).

- **Личные дела** (`/hr/employees`): табельный номер, ИИН, образование, отделение, должность, категория персонала (педагогический / административный / учебно-вспомогательный), вид занятости, ставка, дата приёма, стаж до колледжа (общий стаж считается автоматически), квалификационная категория и срок её действия. Дело заводится для существующего пользователя (например, преподавателя) или для нового сотрудника: тогда создаётся учётная запись **без ролей и без доступа**. Кнопка «Завести личные дела» один раз создаёт дела всем преподавателям по их карточкам.
- **Приказы** (`/hr/orders`): приём, перевод, изменение ставки, увольнение, прочий. Проект → «Подписать»: присваивается номер `К-ГГГГ-NNNNN`, изменения вносятся в личное дело и в карточку преподавателя (расписание и журналы видят новую должность и отделение). Подписанный приказ не меняется — исправление оформляется новым приказом. Увольнение закрывает доступ в дату увольнения: сразу, если дата наступила, иначе командой `php cli.php hr:daily`. Приказ печатается на A4 (PDF через печать браузера).
- **Отпуска и отсутствия** (`/hr/leaves`, `/my/leaves`): сотрудник подаёт заявку (ежегодный, без сохранения, учебный, другое), отдел кадров утверждает или отклоняет с причиной; обе стороны получают уведомления. Больничный лист и командировку отдел кадров вносит по документу — они сразу утверждены. Остаток ежегодного отпуска = положено − утверждено − на рассмотрении за календарный год; заявка сверх остатка и пересекающиеся даты не принимаются. Отсутствующие преподаватели показываются на странице расписания тем, кто его ведёт (`schedule.manage`), — для замен.
- **Квалификация** (`/hr/qualification`): категория и срок, курсы повышения квалификации (часы, сертификат). Напоминания на обзоре HR: категория истекает в ближайшие N дней или истекла, курсов не было более M лет. Отчёт выгружается в Excel (CSV) и на печать.

Настройки в `config/hr.php` — **значения по умолчанию, их нужно сверить с правилами колледжа и Трудовым кодексом РК**: префикс номера приказа, дни ежегодного отпуска по категориям персонала (56 педагогическим, 24 остальным; у сотрудника можно задать своё значение), список категорий, сроки напоминаний (180 дней, 5 лет).

## Несколько колледжей (SaaS)

Одна установка обслуживает много колледжей. Включается в `.env`: `TENANCY=true` (по умолчанию выключено — один колледж, как раньше).

- **Адреса:** `<сайт>/` — страница ввода кода колледжа; `<сайт>/<код>/…` — система колледжа; `<сайт>/platform` — панель владельца.
- **Данные:** у каждого колледжа **своя база данных** (`TENANT_DB_PREFIX` + код), у платформы — своя (`PLATFORM_DB_DATABASE`): колледжи, счета, владельцы, реквизиты. Файлы колледжа — в `storage/private/tenants/<код>/`.
- **Изоляция:** сессия привязана к колледжу (cookie с путём `/<код>/` и проверка на сервере): cookie одного колледжа не работает ни в другом колледже, ни в панели владельца.
- **Панель владельца:** создание колледжа (создаётся база, применяются миграции и базовые данные, администратор колледжа получает временный пароль — показывается один раз), подключение существующей базы, блокировка/разблокировка, новый пароль администратору, использование (студенты, преподаватели, активность за 30 дней, объём базы), сводный отчёт и оплаты по месяцам (CSV), реквизиты для счетов.
- **Подписка:** новый колледж получает пробный период (`trial_days`). Счёт выставляется на N месяцев (цена × месяцы, номер `СЧ-ГГГГ-NNNNN`, печать на A4); кнопка «Оплачен» продлевает срок: оплаченные месяцы продолжают текущий срок или начинаются с даты оплаты, если срок уже истёк.
- **Окончание срока:** за `warn_days` дней администратор колледжа видит напоминание; после срока — льготный период (`grace_days`, задаётся у колледжа) с полным доступом; затем **режим только просмотра**: страницы открываются, изменения (формы и API) не сохраняются, вход, выход, смена языка и пароля работают. «Заблокировать» закрывает доступ полностью.

Управление колледжами в панели владельца:

- **Войти в колледж** — одноразовая ссылка (60 секунд) открывает колледж под его администратором: вверху плашка «Вы вошли как владелец платформы», вход записывается в журнал аудита колледжа, временный пароль администратора менять не требуется. Войти можно только под администратором (не под студентом или преподавателем).
- **Пользователи колледжа** — поиск, роли, последний вход; заблокировать/разблокировать, выдать временный пароль, добавить администратора. Действия пишутся в журнал владельца и в журнал колледжа.
- **Тарифы** — цена в месяц и лимит активных студентов. Колледжу назначается тариф (пустая цена = цена тарифа); при достижении лимита новых студентов добавить нельзя (форма и импорт объясняют причину), в списке колледжей видно «студенты / лимит».
- **Объявления** — всем колледжам или одному, администраторам или всем пользователям, с датами показа; видны вверху страниц колледжа.
- **Резервные копии** — полная SQL-копия базы колледжа (`storage/private/backups/<код>-<дата>.sql.gz`), скачивание из панели.
- **Архив** — доступ закрыт, колледж скрыт из основного списка, данные сохранены; можно вернуть. Удалить базу архивного колледжа можно только после свежей резервной копии и вводом его кода; карточка, счета и копии остаются.

Запуск:

```bash
php cli.php platform:install owner      # база платформы и владелец (временный пароль — один раз)
php cli.php platform:admin <login>      # ещё владелец или новый пароль
php cli.php tenants:list                # колледжи и состояние подписки
php cli.php tenants:migrate             # после обновления: миграции и права во всех колледжах
php cli.php hr:daily                    # по cron: для всех колледжей
php cli.php user:password admin --college=<код>   # любая команда для одного колледжа
```

Пользователю MySQL нужно право `CREATE` на базы с префиксом колледжей. Текущую базу одного колледжа можно подключить в панели: «Новый колледж» → «Подключить существующую базу».

## Тестирование (этап 11)

```bash
php tests/run.php                  # unit-тесты, база не нужна (≈1 с)
php tests/run.php --integration    # плюс интеграционные тесты через HTTP и БД (≈20 с)
php tests/run.php --filter=Access  # только классы с «Access» в имени
```

Интеграционные тесты **никогда не трогают рабочую базу**. Они делают так:
- создают отдельную базу `<DB_DATABASE>_test` и заново накатывают в неё миграции и демо-данные;
- поднимают встроенный PHP-сервер на свободном порту.

Имя тестовой базы обязано заканчиваться на `_test`. Другой сервер БД задаётся переменными `TEST_DB_HOST`, `TEST_DB_PORT`, `TEST_DB_USERNAME`, `TEST_DB_PASSWORD`, `TEST_DB_DATABASE`.

| Набор | Что проверяет |
|---|---|
| Unit | валидатор (ИИН, даты, числовые диапазоны), расчёт итоговой оценки по схеме, маршрутизатор, QR-код, CSV для Excel, транслитерация логинов, аудитория анкет; совпадение ключей и подстановок ru/kk; права в ролях, меню и маршрутах; статический анализ: суперглобальные переменные, данные запроса в SQL, опасные функции, слабые хэши, SQL в шаблонах |
| Права доступа | каждый маршрут либо явно публичный или личный (профиль, выход), либо проверяет право — удаление проверки сразу ломает тест; каждая страница открыта каждой из 8 ролей: доступ строго по правам, аноним уходит на вход, чужие отделения и записи закрыты |
| Вход и сессии | неверный пароль, обязательная смена временного пароля, CSRF для форм и API, выход только POST, блокировка подбора, заголовки безопасности, флаги cookie |
| Импорт и API | Excel-импорт: предпросмотр без записи, только корректные строки, область доступа, одноразовые пароли; `/api/workloads`, `/api/document-requests`; главные страницы студента и преподавателя |
| Бизнес-процессы | журнал (шкала, история изменений, запрет студенту и чужому отделению), итог совпадает со схемой, заявление → справка → публичная проверка без персональных данных, анонимная анкета не хранит личность, нагрузка не превышает учебный план, родитель видит только своего ребёнка |
| XSS | данные пользователя экранируются на страницах |
| Схема и скорость | структура БД, все миграции применены, тяжёлые страницы отвечают быстрее 1,5 с |

Тесты написаны без внешних библиотек: в сети колледжа Composer не загружает пакеты. Названия проверок совпадают с PHPUnit (`assertSame` и др.), поэтому перенос на PHPUnit не потребует переписывать тесты.

## Внедрение (production)

1. **Сервер**:
   - PHP 8.3+ с `pdo_mysql`, `mbstring`, `json`, `fileinfo`, `openssl` и включённым OPcache;
   - MySQL 8 (или MariaDB 10.4+), Apache с `mod_rewrite` (желательно `mod_headers` и `mod_deflate`);
   - HTTPS;
   - `upload_max_filesize` и `post_max_size` не меньше 8M.
2. **Код**:
   - скопируйте проект без папок `tests/` и `storage/logs/*`;
   - корень сайта — папка `public/`;
   - выполните `composer dump-autoload -o` (если Composer нет, работает встроенный загрузчик);
   - дайте веб-серверу права на запись только в `storage/`.
3. **`.env`** (скопируйте из `.env.example`):
   - `APP_ENV=production`, `APP_DEBUG=false`;
   - `APP_URL=https://<адрес колледжа>` — на этот адрес ведут QR-коды документов;
   - `SESSION_SECURE_COOKIE=true`;
   - отдельный пользователь MySQL с правами только на свою базу;
   - `SEED_ADMIN_PASSWORD` оставьте пустым: пароль сгенерируется и выведется один раз.
4. **База**:
   - `php cli.php db:create`, `php cli.php migrate`, `php cli.php db:seed`;
   - **без** `--demo`: в production демо-данные запрещены.
5. **Проверка**: `php cli.php check` и `php cli.php db:check`. Строк `[FAIL]` быть не должно.
6. **Первый вход**:
   - войдите под `admin` и смените пароль;
   - в «Настройках» заполните название, адрес и подписанта справок;
   - заведите учебный год, справочники, схему оценивания, пользователей.
7. **Резервные копии** (ежедневно, по cron):
   - `mysqldump --single-transaction --routines <база> | gzip > backup-$(date +%F).sql.gz`;
   - копия папки `storage/private/` (вложения заявлений);
   - хранить вне сервера.
8. **Обновление версии**:
   - резервная копия;
   - замена кода;
   - `php cli.php migrate` и `php cli.php db:seed` (синхронизирует роли и права, существующие данные не меняет);
   - `php cli.php check`.
   До выкладки прогоните `php tests/run.php --integration` на тестовом сервере.
9. **Наблюдение**: журнал ошибок — `storage/logs/app-ГГГГ-ММ-ДД.log`; действия пользователей — раздел «Журнал аудита».

## Зависимости и сеть

Сторонние библиотеки (Bootstrap 5.3.3, Bootstrap Icons 1.11.3, Chart.js 4.4.1) лежат в
`public/assets/vendor`. Хеши Bootstrap и Bootstrap Icons совпадают с официальными SRI.
В сети, где TLS-трафик перехватывается сертификатом, которого нет в хранилище PHP, Composer не
загружает пакеты (`curl error 60`). Не отключайте проверку TLS; при необходимости укажите Composer
корневой сертификат вашей сети через `COMPOSER_CAFILE` — это решение администратора.

## Безопасность (реализовано на этапе 1)

`password_hash`/`password_verify` (+ rehash), выравнивание времени ответа для несуществующих
логинов, регенерация ID сессии при входе и каждые 15 мин, HttpOnly/SameSite cookies (Secure под
HTTPS), тайм-аут неактивности, CSRF для всех изменяющих запросов (форма `_token` и заголовок
`X-CSRF-Token`), ограничение попыток входа (логин+IP и IP), журнал аудита входов/выходов,
экранирование вывода `e()`, CSP без inline-скриптов, `X-Frame-Options`, ошибки без SQL и путей
(подробности только при `APP_DEBUG=true` — не включайте на production), защита от open redirect.
